# officeACE 数据浏览器

在本地网页里浏览 `dd/hh/mm/*.json` 格式的回流数据，并配置为对话回放。固定顶栏可切换“数据浏览 / 对话回放”。数据根目录在页面上填写；数据文件由本机 Python 服务读取。

## 启动

需要 Python 3.9 或更新版本，无需安装 npm / pip 依赖。

```bash
cd /Users/xinfanchen/项目资料/华为实习/数据准备/officeACE/data-web
python3 server.py
```

浏览器打开 <http://127.0.0.1:8766>。macOS 也可以双击 `start.command`；命令行可以使用 `./start.sh`。终端按 `Ctrl+C` 停止。

可选启动参数：

```bash
python3 server.py --port 8767
python3 server.py --data-root /absolute/path/to/data
```

## 使用

1. 在页面填写数据根目录的绝对路径，点击扫描。根目录是 `dd` 的上一级，例如：

   ```text
   /data/officeACE/
   ├── 18/
   │   └── 23/
   │       └── 59/events.json
   └── 19/
       ├── 08/
       │   └── 00/events.json
       └── 09/
           └── 30/events.json
   ```

2. 设置起止日、时、分。时间区间按照目录时间连续比较，包含两端，支持跨小时、跨天。例如 `18 / 23 / 59 → 19 / 08 / 00` 会包含这两个分钟目录。
3. 在“字段筛选”里打开字段选择框，搜索字段名并选择完整路径，然后输入关键字，或使用“存在 / 不存在”判断字段是否存在。点击“添加条件”可以组合多个字段，最多 20 个条件；多个条件和目录时间范围同时生效。字段筛选和左侧展示字段的勾选相互独立。
4. 在左侧字段树选择展示字段。对象、数组及其子字段都有复选框；勾选父级会选择其所有子字段，部分选中时显示半选状态。可搜索字段名。
5. 在表格或 JSON 视图查看选择的字段，翻页浏览结果。展开单条记录可查看投影后的 JSON；导出仅包含当前页与当前选中的字段。
6. 文件新增、删除或更新后，重新扫描当前目录。

`dd` 只有日号，没有年月。请将一个月份的数据放在一个根目录下；跨月数据应分别选择根目录。

“包含”匹配不区分大小写；“等于”匹配区分大小写。“区间”支持任意字段的数字或 ISO 日期时间，包含两个端点，也可以只填写一端。数字两端应与源数据使用相同单位；日期建议显式带时区，例如 `2026-10-19T09:00:00+08:00`。未带时区的日期按 UTC 解释。空关键字或两端都为空的区间不参与筛选。

例如真实记录为：

```json
{
  "start": "2026-10-20T09:00:00+08:00",
  "resourceAttributes": {
    "host.name": "company-pc",
    "user.id": "employee-01"
  }
}
```

选择 `resourceAttributes["host.name"]`，再输入 `company-pc` 即可匹配。添加第二个条件并选择 `resourceAttributes["user.id"]` 可以同时筛选用户。

路径中的点号有明确区别：`resourceAttributes["host.name"]` 表示名为 `host.name` 的一个键；`resourceAttributes.host.name` 表示 `host` 对象下的 `name`。字段选择器直接使用扫描得到的完整路径，不会把点号键错误拆开。数组元素路径显示 `[]`，例如 `events[].attributes["user.id"]`；该数组中任一元素匹配即可，多次命中不会重复记录。多个数组条件各自判断是否存在匹配元素。

布尔值用 `true` / `false`，空值用 `null` 筛选；不存在的字段不会匹配。选择对象或数组整体时，会在它的 JSON 内容中匹配关键字。

## 相同记录过滤与重复来源

数据浏览页可勾选“过滤相同记录”，对话页默认开启。去重按**整条原始 JSON 内容**比较，忽略对象键的排列顺序，保留数组顺序；不受展示字段勾选影响。原始文件不会修改，时间范围与字段筛选先执行，再在匹配记录中去重。页面显示原始条数、过滤的重复条数，以及代表记录合并了多少份副本。

展开单条记录并点击“查看原始记录与重复来源”，或展开对话气泡下的来源，可查看相同完整 JSON 在哪些文件、哪些条目出现。重复来源在全目录范围内查找，最多展示前 200 个位置，并提供总数。

原来的浏览器按每个文件中的原始条目逐条展示，没有去重。仅凭“出现三次”无法判断是否是三份回流文件、单个文件内重复写入，或未展示的元数据不同；应结合完整 JSON 和来源位置判断。正文相同但时间或其他字段不同的记录会保留。

## 对话回放

1. 先在“数据浏览”中扫描目录，再从固定顶栏切换“对话回放”。两页共享数据目录，对话页有独立的筛选条件。
2. 打开“字段与筛选配置”，选择主机字段（例如 `resourceAttributes["host.name"]`）和消息时间字段（例如 `start`）。不选会话 ID 时，每台主机是一段对话；选择会话 ID 后，侧边栏按主机分组并列出不同会话。
3. 选择角色、正文、附件、工具调用字段，并配置角色的实际取值。默认识别 `user/human`、`assistant/agent/ai`、`tool/function/tool_call/tool_result`。可以把事件类型字段映射为角色或工具事件类型。
4. 若记录里存放整个消息数组，例如 `body.messages`，先选择“消息列表”为该数组，再为正文、角色、时间选择数组内完整路径，如 `body.messages[].content`、`body.messages[].role`、`body.messages[].start`。不选消息列表时，一条记录是一条消息。数组中的消息也会跨记录按时间排序。
5. 若没有统一角色字段，可添加“按字段识别消息类型”的规则：指定用户 / Agent / 工具，用字段存在性或字段值判断，也可为该类型单独映射正文。规则按排列顺序首次命中生效，优先于角色取值；同一规则内的条件同时满足。没有识别出来的记录会保留并标明，避免悄悄丢数据。
6. 使用“记录筛选”设置必须包含的字段（“存在”），以及需要匹配的字段值（“包含 / 等于 / 区间”）。字段存在但值为 `null`、`false`、`0` 时，“存在”仍然匹配。筛选作用于原始记录；匹配记录中的整个消息数组会保留。
7. 点击“应用配置并载入”。侧边栏可搜索主机或会话 ID；每次加载最多 100 条完整消息，点击“载入后续消息”继续，已显示与总数都会标明。消息正文、工具详情和原始 JSON 不做内容截断。

用户消息和附件右对齐，Agent 与工具左对齐；时间在组件右下角显示为灰色小字。工具默认收起，点击可查看完整工具字段及原始消息。附件以文件卡片呈现，展开查看完整附件元数据，不会自动访问附件地址。正文没有映射或该字段缺失时，展示完整消息 JSON。此页为只读回放。

时间支持 ISO 日期以及 Unix 秒 / 毫秒 / 微秒 / 纳秒，可自动识别或指定单位；缺失或无法识别的时间保留并排到最后。时间相同的消息按原始记录和数组位置稳定排序。显示时间采用浏览器本地时区，原始值保留在时间提示中。映射和规则保存在当前浏览器，重新连接目录后复用仍存在的字段路径。

## 数据格式

支持以下 UTF-8 JSON 形式，以及 `.jsonl` / `.ndjson` 逐行对象文件：

- 对象数组：`[{"start": "…", "host": {"name": "…"}, "user": {"id": "…"}}]`。
- 包装对象：`{"records": [...]}`，同样识别 `events`、`data`、`items` 数组。
- Elasticsearch 响应：`{"hits": {"hits": [{"_source": {...}}]}}`，展示 `_source` 内容。
- 单条对象记录。顶层已有 `start`、`host`、`user`、`host.name` 或 `user.id` 时，优先视为单条记录，保留其中的嵌套数组。

筛选器和展示字段均通过完整路径区分字段。字段树覆盖当前目录中的全部字段，包含仅在部分记录中出现的字段；切换筛选和翻页时保留已选展示字段。

无法解析的文件或 NDJSON 行会显示警告，其余有效数据仍可查询。目录名可以是一位或两位数字；日为 1–31，时为 0–23，分为 0–59。不跟随数据目录中的符号链接。

## 演示数据

项目附有合成演示数据生成器：

```bash
python3 scripts/generate_demo.py
```

生成 `demo-data/`，默认包含 6 个文件、每个文件 1,000 条记录，共 6,000 条。页面点击演示数据按钮即可加载。所有用户名、主机名、事件均为虚构。演示覆盖嵌套对象、对象数组、数组内嵌套对象、布尔值、空值以及只在部分记录出现的字段。

演示数据也包含 `resourceAttributes["host.name"]` 和 `resourceAttributes["user.id"]`，可以用 `office-bj-01`、`demo-user-001` 验证组合筛选。

另有对话示例生成器：

```bash
python3 scripts/generate_conversation_demo.py
```

生成 `chat-demo-data/`：两台主机、各两段会话，共 24 条唯一记录，每条出现三份，共 72 条。对话页点击“对话示例”可直接验证左右对齐、附件、工具调用、时间排序及 72 → 24 去重。示例全部为虚构数据。

1.2 更新包已附带这份小型合成对话示例，不含真实回流数据或 `.cache/`。

## 更新已有的内网版本

1. 更新 `server.py`、`conversation.py` 和整个 `public/` 目录（或使用完整更新包），保留内网电脑自己的数据目录与 `.cache/`。
2. 停止旧的 Python 服务，再运行 `python3 server.py`，并刷新网页。仅更新前端而不重启后端时，页面会提示版本不支持。
3. 扫描原来的数据根目录，再从字段选择器选择完整嵌套路径。已有记录索引可以继续使用，新增缓存表和记录指纹列会自动创建，不需要删除旧索引。旧记录的完整内容指纹在首次开启去重时按批补齐。

首次筛选某个字段时，后端仅为当前时间范围涉及的文件建立字段索引；翻页和再次筛选复用索引。扩大时间范围时补充索引；源文件更新或删除后重新扫描，会自动清除相应的过期字段索引。整个过程在内网电脑本地完成，无需上传数据，也无需下载依赖。

## 本地实现

- `server.py`：HTTP 服务、文件扫描、SQLite 索引、查询与分页。
- `conversation.py`：对话索引、配置映射、分组、排序、消息还原。
- `public/`：原生 HTML / CSS / JavaScript 页面。
- `scripts/generate_demo.py`：可重复生成的合成数据。
- `scripts/generate_conversation_demo.py`：带三份重复来源的合成对话。
- `tests/`：后端集成测试。
- `.cache/`：可重建的本地索引，含原始记录的副本；停止服务后可以删除。

浏览器每次只接收当前页的记录。扫描按文件读取并写入 SQLite，避免把整个数据集同时放进内存；单个 JSON 文件仍需能放入内存。索引在重新扫描时更新。服务默认监听本机 `127.0.0.1`，页面资源和数据查询均由本地提供。
